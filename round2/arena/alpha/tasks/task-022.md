# Task 022: Cycle 9 三任务推进

## [需求] Task A — 个性化排序最小闭环
要什么：让 `paper-digest digest --topic ...` 在现有 topic 相关度之外，额外读取用户偏好（优先来自订阅/兴趣配置），对论文做二次加权排序。
为什么：这是项目 brief 的核心差异化方向，也是 Alpha 相比 Beta 最该拉开的产品深度。
优先级：P0

约束：
- 仅做最小可用实现，禁止大改架构
- 无偏好时行为必须与当前版本一致
- 单次提交保持小步，不要 BLOAT

验收：
- 同 topic 下，命中用户偏好的论文排序前移
- 无偏好配置时结果与旧逻辑一致
- 相关测试为绿

---

## [需求] Task B — subscribe 真实化为偏好入口
要什么：把 `subscribe` 从 placeholder 变成本地可持久化的偏好配置入口，至少能记录 topic 和 channel。
为什么：个性化排序需要真实配置来源；否则 README 和产品叙事会脱节。
优先级：P0

约束：
- 只做本地配置文件，不做真实推送
- CLI 反馈要清晰，路径要稳定
- 配置结构要能被排序层直接消费

验收：
- 运行 `paper-digest subscribe --topic "RAG" --channel email` 后能写入本地配置
- 再次运行时不会报错或破坏旧配置
- CLI 输出明确说明已保存

---

## [需求] Task C — 测试护栏 + 安装验证 + README 收口
要什么：为 Task A/B 补测试，并验证 `pip install -e .` 与 CLI 入口无回归，同时让 README 安装与功能表述和真实实现对齐。
为什么：测试永远是任务之一；没有验证的个性化和订阅入口只会积债。
优先级：P1

约束：
- 先补关键路径测试，不做无意义堆量
- README 只能写已经真实存在的能力
- 安装验证必须可复现

验收：
- 新增/更新测试覆盖偏好命中、无偏好回退、订阅持久化、CLI 成功路径
- `pytest` 通过
- `pip install -e .` 后 `paper-digest --help` 可运行
- README 中安装说明与功能状态一致
