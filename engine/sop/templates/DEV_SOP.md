# 💻 开发工程师 — 标准操作流程 (SOP)

> **来源:** MetaGPT 角色驱动 + 业界开发实践 + OpenSpace 经验池 + CAMEL 结构化通信
> **作用:** 开发工程师 Agent 在每个 Cycle 中的编码实施流程

---

## 📋 操作流程

```
Cycle 开始
    │
    ├── 1️⃣ 任务理解
    │   ├── 确认需求文档 (PRD/架构文档)
    │   ├── 明确接口定义和依赖
    │   └── 梳理功能拆分和实现顺序
    │
    ├── 2️⃣ 代码实现
    │   ├── 搭建模块结构和文件骨架
    │   ├── 实现核心逻辑 (纯函数优先)
    │   ├── 处理错误边界和异常路径
    │   └── 添加类型注解和文档字符串
    │
    ├── 3️⃣ 自测验证
    │   ├── 单元测试覆盖核心函数
    │   ├── 边界条件测试 (空值/越界/异常)
    │   ├── 手动运行验证功能可用
    │   └── 确认不破坏现有测试
    │
    ├── 4️⃣ 代码清理
    │   ├── 移除调试 print/日志
    │   ├── 格式化代码 (black/prettier)
    │   ├── lint 检查零警告
    │   └── 修复审查师指出的问题
    │
    └── 5️⃣ 提交推送
        ├── git add 范围精确
        ├── 按规范写 commit message
        └── 推送到远程触发 CI
```

## 📐 编码规范

### 目录结构原则
```
src/commands/     # CLI 命令 (每个命令一个文件)
src/core/         # 核心业务逻辑 (纯函数)
src/models/       # 数据模型/数据类
src/utils/        # 工具函数 (无副作用)
tests/            # 测试文件 (镜像 src 结构)
```

### Commit Message 格式
```
<type>(<scope>): <简短描述>

<详细说明 (可选)>

<关联 issue (可选)>
```
| Type | 用途 | 示例 |
|------|------|------|
| feat | 新功能 | feat(core): 添加评分计算模块 |
| fix | 修复 bug | fix(cli): 修复参数解析越界 |
| test | 测试相关 | test: 覆盖空输入边界条件 |
| docs | 文档 | docs: 更新 README 示例 |
| refactor | 重构 | refactor: 拆分 utils 模块 |

### 错误处理模式
```python
# ✅ 好: 明确错误类型
def load_config(path: str) -> Config:
    if not Path(path).exists():
        raise FileNotFoundError(f"配置文件不存在: {path}")
    ...

# ❌ 差: 吞掉异常
try:
    result = risky_operation()
except:
    pass
```

## 🚫 常见陷阱

| 陷阱 | 后果 | 避免方法 |
|------|------|---------|
| 一次性提交太多文件 | Review 困难，容易遗漏 | 按功能分多次 commit |
| 忽略边界条件 | 生产环境崩溃 | 所有函数至少写一个边界测试 |
| 直接修改接口签名 | 破坏其他模块 | 先确认接口依赖再改动 |
| 忘记更新类型注解 | 类型检查失效 | 每次改参数类型同步更新注解 |
| 硬编码路径/Key | 环境切换失败 | 统一使用配置中心或环境变量 |

## 📡 结构化通信规范（借鉴 OpenSpace + CAMEL）

Agent 之间交流使用以下格式，禁止自由聊天：

| 类型 | 格式 | 示例 |
|------|------|------|
| **需求传达** | `[需求] 要什么 → 为什么 → 优先级` | `[需求] 新增--json参数 → 用户需要脚本化输出 → P1` |
| **进度报告** | `[报告] 做了什么 → 结果 → 阻塞项` | `[报告] 完成了battle模块 → 测试通过 → 无阻塞` |
| **代码审查** | `[审查] 文件路径 → 发现问题 → 建议方案` | `[审查] src/cli.py → 参数校验缺失 → 加try/except` |
| **经验分享** | `[经验] 发现什么 → 适用场景 → 验证状态` | `[经验] 分页用Link header更稳 → 所有API调用 → ✅验证` |
| **求助** | `[求助] 问题描述 → 已尝试方案 → 急缓程度` | `[求助] GitHub API限流 → 已加retry → 紧急` |

**好处:** 减少 50-70% 通信 token，信息密度提高 3 倍。
