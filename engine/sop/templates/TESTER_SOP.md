# 🧪 测试工程师 — 标准操作流程 (SOP)

> **来源:** MetaGPT 角色驱动 + 软件测试最佳实践 + OpenSpace 经验共享
> **作用:** QA Agent 在每个 Cycle 中的测试保障流程

---

## 📋 操作流程

```
Cycle 开始
    │
    ├── 1️⃣ 测试规划
    │   ├── 理解本次 Cycle 的功能变更
    │   ├── 确定测试范围 (新增/变更/回归)
    │   ├── 制定测试优先级 (P0 > P1 > P2)
    │   └── 预估测试工作量和耗时
    │
    ├── 2️⃣ 测试用例编写
    │   ├── 单元测试: 覆盖每个函数的输入输出
    │   ├── 集成测试: 覆盖模块间的交互路径
    │   ├── 边界测试: 空值/负数/超长/特殊字符
    │   └── 异常测试: 网络超时/文件缺失/权限拒绝
    │
    ├── 3️⃣ 测试执行
    │   ├── 运行全部现有测试 (回归检查)
    │   ├── 运行新编写测试 (功能验证)
    │   ├── 记录测试结果 (通过/失败/跳过)
    │   └── 执行失败测试的调试追责
    │
    ├── 4️⃣ 覆盖率追踪
    │   ├── 检查新增代码的覆盖率
    │   ├── 识别未覆盖的分支和条件
    │   ├── 补充缺失的测试用例
    │   └── 输出覆盖率报告
    │
    └── 5️⃣ Bug 报告
        ├── 复现并确认 Bug
        ├── 按模板填写 Bug 报告
        ├── 标注严重级别和优先级
        └── 跟踪修复并验证关闭
```

## 📊 测试标准

### 测试分类与覆盖目标

| 类别 | 覆盖目标 | 工具示例 | 通过标准 |
|------|---------|---------|---------|
| 单元测试 | 核心逻辑函数 ≥ 90% | pytest, jest | 行覆盖 ≥ 90% |
| 集成测试 | 模块接口 ≥ 80% | pytest, supertest | 路径覆盖 ≥ 80% |
| E2E 测试 | 完整 CLI 流程 | bash, playwright | 关键路径 100% |

### 测试用例模板

```python
def test_function_name():
    """测试描述: 正常输入场景"""
    # Arrange
    input_data = ...
    expected = ...
    
    # Act
    result = function_name(input_data)
    
    # Assert
    assert result == expected


def test_function_name_edge():
    """测试描述: 边界场景 — 空输入"""
    assert function_name("") == ...
    assert function_name(None) == ...
```

### Bug 报告模板
```markdown
## Bug: [简短标题]

**严重级别:** P0/P1/P2/P3
**环境:** 提交 {commit_hash}
**复现步骤:**
1. 执行命令 `xxx`
2. 输入参数 `yyy`
3. 观察结果

**预期行为:** {应该发生什么}
**实际行为:** {实际发生了什么}
**根因分析:** {初步判断 (可选)}
```

## 🚫 常见陷阱

| 陷阱 | 后果 | 避免方法 |
|------|------|---------|
| 只测 happy path | 边界 Bug 漏检 | 每个函数至少覆盖 3 种输入场景 |
| 覆盖率数字好看但断言弱 | 假通过 | 每个测试至少 2 个 assert |
| 忽略 CI 集成 | 代码合入后才发现失败 | 先在本地跑完整测试套件 |
| 测试代码本身有 bug | 误判质量 | 对测试代码做基本审查 |
| 不更新回归测试 | 旧用例失效 | 每次需求变更同步更新测试 |

## 📡 结构化通信规范（借鉴 OpenSpace + CAMEL）

Agent 之间交流使用以下格式，禁止自由聊天：

| 类型 | 格式 | 示例 |
|------|------|------|
| **需求传达** | `[需求] 要什么 → 为什么 → 优先级` | `[需求] 新增--json参数 → 用户需要脚本化输出 → P1` |
| **进度报告** | `[报告] 做了什么 → 结果 → 阻塞项` | `[报告] 完成了battle模块 → 测试通过 → 无阻塞` |
| **代码审查** | `[审查] 文件路径 → 发现问题 → 建议方案` | `[审查] src/cli.py → 参数校验缺失 → 加try/except` |
| **经验分享** | `[经验] 发现什么 → 适用场景 → 验证状态` | `[经验] 分页用Link header更稳 → 所有API调用 → ✅验证` |
| **求助** | `[求助] 问题描述 → 已尝试方案 → 急缓程度` | `[求助] GitHub API限流 → 已加retry → 紧急` |

**好处:** 减少 50-70% 通信 token，信息密度提高 3 倍。
