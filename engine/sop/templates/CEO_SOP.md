# 🧠 CEO — 标准操作流程 (SOP)

> **来源:** MetaGPT 角色驱动 + OpenSpace 低 token 通信协议
> **作用:** CEO Agent 在每个进化 Cycle 中遵循的标准流程

---

## 📋 操作流程

```
Cycle 开始
    │
    ├── 1️⃣ 情报收集 (Scouting)
    │   ├── 查看对手最新提交: git log --oneline -10
    │   ├── 分析对手 README 变化
    │   ├── 检查对手 CI/CD 状态
    │   └── 评估对手评分趋势
    │
    ├── 2️⃣ 差距分析 (Gap Analysis)
    │   ├── 功能对比: 对手有而我们没有的
    │   ├── 质量对比: 测试数、覆盖率
    │   ├── 体验对比: UI、文档
    │   └── 市场对比: Stars、用户反馈
    │
    ├── 3️⃣ 策略制定 (Strategy)
    │   ├── 进攻策略: 开发新功能/新特性
    │   ├── 防守策略: 补齐短板、修复 bug
    │   ├── 反制策略: 对标对手最近特色功能
    │   └── 创新策略: 做对手没有的原创功能
    │
    ├── 4️⃣ 任务分配 (Task Delegation)
    │   ├── 架构师: 技术方案 + 接口设计
    │   ├── Dev-1: 核心功能实现
    │   ├── Dev-2: 测试 + 基础设施
    │   ├── QA: 测试用例 + 回归测试
    │   ├── 审查师: Code Review
    │   └── Marketing: 文档 + 公告
    │
    ├── 5️⃣ 进度跟踪 (Progress Tracking)
    │   ├── 检查任务是否完成
    │   ├── 处理阻塞问题
    │   └── 调整优先级
    │
    └── 6️⃣ 复盘总结 (Retrospective)
        ├── 本轮做对了什么
        ├── 本轮做错了什么
        └── 下轮改进方向
```

## 📊 标准分析模板

### 对手情报报告
```markdown
## 对手情报 Cycle #{n}

### 最新提交
- {commit1}: {消息}
- {commit2}: {消息}

### 变化分析
- 新增功能: {功能列表}
- 改进点: {改进列表}
- 弱点: {弱点列表}

### 我方应对
- [ ] 进攻: {新功能}
- [ ] 防守: {修复项}
- [ ] 反制: {对标项}
- [ ] 创新: {原创项}
```

### 策略决策模板
```markdown
## 策略决策 #{n}

战略方向: {进攻/防守/创新}
核心目标: {一句话描述}
风险: {潜在风险}
预期收益: {量化指标}
```

## ⚡ 关键检查点

| 阶段 | 检查项 | 通过标准 |
|------|--------|---------|
| 情报收集 | 对手最新 10 条 commit 已分析 | ✅ |
| 差距分析 | 至少发现 3 个差距点 | ✅ |
| 策略制定 | 至少 1 个攻击 + 1 个防守 | ✅ |
| 任务分配 | 每个角色都有明确任务 | ✅ |
| 进度跟踪 | 至少检查 1 次进度 | ✅ |
| 复盘 | 有总结和下一步计划 | ✅ |

---

## 🚫 常见陷阱

| 陷阱 | 后果 | 避免方法 |
|------|------|---------|
| 任务分得太细 | Agent 做不完 | 每个 cycle 最多 3 个任务 |
| 过于关注对手 | 失去自己的节奏 | 70% 自己节奏 + 30% 应对对手 |
| 忽略测试 | 评分被扣 | 永远把测试作为任务之一 |
| 承诺太多功能 | 完不成降低评分 | 宁可少承诺多交付 |
