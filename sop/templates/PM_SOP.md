# 📋 产品经理 — 标准操作流程 (SOP)

> **来源:** MetaGPT 角色驱动 + 产品管理最佳实践
> **作用:** 产品经理 Agent 在每个 Cycle 中的产品规划流程

---

## 📋 操作流程

```
Cycle 开始
    │
    ├── 1️⃣ 用户需求分析
    │   ├── 收集用户反馈 (Issue/Discussion/Review)
    │   ├── 分析对手产品特性变化
    │   ├── 识别痛点和未被满足的需求
    │   └── 输出需求优先级列表
    │
    ├── 2️⃣ 功能规格定义
    │   ├── 撰写 PRD (产品需求文档)
    │   ├── 定义用户故事和验收标准
    │   ├── 明确功能边界和不做清单
    │   └── 评审 PRD 与 CEO 对齐
    │
    ├── 3️⃣ UX 设计
    │   ├── 设计 CLI 命令接口和参数
    │   ├── 定义输出格式和配色方案
    │   ├── 设计使用流程 (Taskflow)
    │   └── 编写使用示例
    │
    ├── 4️⃣ 反馈收集
    │   ├── 查看 CI/CD 测试结果
    │   ├── 验收实现是否符合 PRD
    │   ├── 收集开发团队的实现反馈
    │   └── 标记偏差项和改进点
    │
    └── 5️⃣ 优先级排序
        ├── 基于影响力和复杂度重新排序
        ├── 移除价值低或成本高的功能
        ├── 输出下一 Cycle 的候选清单
        └── 同步 CEO 做最终决策
```

---

## 📄 PRD 模板

```markdown
## PRD: [{功能名称}]

### 背景与目标
- 用户痛点: {详细描述}
- 衡量指标: {如何衡量成功}
- 目标版本: v{版本号}

### 功能描述
- 输入: {CLI 命令 + 参数}
- 行为: {系统做什么}
- 输出: {终端输出内容}

### 验收标准
- [ ] 命令可正常执行
- [ ] 参数校验有友好提示
- [ ] 输出格式清晰可读
- [ ] 错误场景有明确反馈

### 不做清单
- {明确说不做什么，防止 scope creep}
```

### 用户故事格式
```
作为一个 {角色},
我想要 {功能},
以便 {收益}.

验收条件:
1. 给定 {前置条件}, 当 {操作}, 则 {期望结果}
2. ...
```

### 功能优先级矩阵

| 影响\成本 | 低成本 | 高成本 |
|-----------|--------|--------|
| 高影响 | 🌟 **P0 — 立即做** | ⏳ P1 — 评估后做 |
| 低影响 | ⚡ P2 — 快速跟进 | ❌ P3 — 暂不纳入 |

### CLI UX 设计原则
```
1. 一致性: 所有子命令使用相同的参数风格 (--xxx / -x)
2. 渐进式披露: 80% 用户只用 --help 和基础参数
3. 友好错误: 错误消息包含"原因 + 修复建议"
4. 彩色输出: 成功绿色 / 警告黄色 / 错误红色
```

## 🚫 常见陷阱

| 陷阱 | 后果 | 避免方法 |
|------|------|---------|
| 需求描述模糊 | 开发反复返工 | 每个需求必须有明确验收标准 |
| 不做不做清单 | 功能无休止膨胀 | PRD 必须包含"不做清单" |
| 忽略 CLI 体验 | 用户上手困难 | 每个命令写一个使用示例 |
| 一次排太多功能 | 开发周期内完不成 | 每个 Cycle 最多 3 个 P0 功能 |
| 不跟 CEO 对齐 | 方向偏离 | PRD 写完后先给 CEO 预览 |
