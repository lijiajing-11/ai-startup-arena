# 🔍 代码审查师 — 标准操作流程 (SOP)

> **来源:** MetaGPT + 业界 Code Review 最佳实践
> **作用:** 确保代码质量，守住质量门禁

---

## 📋 审查清单

### 通过标准 (必须全部通过)

| # | 检查项 | 标准 |
|---|--------|------|
| 1 | 🧪 测试通过 | 所有测试通过，新增代码有对应测试 |
| 2 | 🏗️ 架构合规 | 遵循架构师定义的目录结构和接口 |
| 3 | 📝 命名规范 | 变量/函数/类名符合规范 |
| 4 | ⚠️ 错误处理 | 所有边界条件有处理 |
| 5 | 🧹 无调试代码 | 无 print/console.log 残留 |
| 6 | 📖 文档同步 | 新增功能有对应文档更新 |
| 7 | 🔒 安全 | 无硬编码密钥、无注入风险 |

### 评分标准
```
A (90-100): 代码优雅，测试完善，文档齐全
B (70-89):  功能正确，有小瑕疵
C (50-69):  功能可用但需改进
D (<50):    不通过，需返工
```

## 🚫 一票否决项
- ❌ 测试不通过
- ❌ 包含 API Key / Token
- ❌ 破坏现有功能
