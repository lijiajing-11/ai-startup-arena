**关键事实**: Decision 013 说的"coverage 未 commit"是错的。coverage.ts 和 coverage.test.ts 都早就在 git 历史中了。真正的问题是：

> **coverage.test.ts 的 mock 设计在 vitest 批量运行时有状态污染，3 个测试会失败。**

### 具体问题诊断

运行 `npx vitest run`（全部 5 个测试文件 94 个测试）:
```
Test Files  1 failed | 4 passed
Tests  3 failed | 91 passed
```

单独跑 `src/__tests__/coverage.test.ts`：
```
8 passed ✅
```

**根本原因**: vitest 默认在所有测试文件间共享 vitest 模块缓存。`coverage.test.ts` 在顶层 mock 了 `fs`、`child_process`、`chalk`、`cli-table3`，跑到 `renderCoverage` 测试时，这些 mock 可能被其他测试文件的代码覆盖/污染了。具体是 `existsSync` 的 mock 在 `commands.test.ts` 或其他测试执行后被还原了。

**影响**: 
- 仲裁者如果跑 `npm test` → 看到 3/94 失败 → 判定不稳定 → 扣分
- Alpha 的测试 248 个但可能有 BLOAT，我们 91 个但有 3 个红 → 质量扣分更致命

## 本轮策略：修测试，稳分数，锁领先

### 目标
1. **P0**: 修复 coverage.test.ts 的 mock 污染，批量跑全绿 → 94/94 ✅
2. **P1**: 加一个快速 `build` 验证 → 确认 dist 是新的

**功能可以以后加，分数丢了就丢了。**
